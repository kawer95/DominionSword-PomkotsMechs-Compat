# 庞科特机甲（Pomkots Mechs alpha.8）优化建议

> 本文面向模组原作者，基于对 alpha.8 源码的审查与游戏内实测，列出原有模组自身可以优化的地方，供作者参考。不涉及任何第三方附属的实现方案。

## 1. 近战武器伤害盒：旋转后只取两个对角点，范围会塌缩

所有近战武器（Takao / Tsurugi / Kagenobu / Tenpou / Jinba / Gassan / Mitake）的伤害判定都是同一个写法：

```java
var pilePos1 = new Vec3(6.5 * isRight(), 4.0F, 18F)
        .yRot((float) Math.toRadians(-getYRot()))
        .add(position());
var pilePos2 = new Vec3(-6.5 * isRight(), -4F, -4F)
        .yRot((float) Math.toRadians(-getYRot()))
        .add(position());

for (var ent : world.getEntities(null, new AABB(pilePos1, pilePos2))) {
    ...
}
```

### 问题

`new AABB(p1, p2)` 只对**两个对角点**取 min/max。挥击体积是一个绕机甲旋转的盒子，当机甲不正对世界坐标轴时，这两个点只是旋转盒的一对对角，其 min/max 覆盖的是旋转盒的**对角线细缝**，而不是旋转盒的完整轴对齐包围盒。

实测：机甲转向约 27° 时，Takao 的伤害盒在 X 方向只剩约 1.4 格宽，站在正前方数格的目标完全不在盒内，整次挥击不产生击退与伤害，但动画与特效正常播放——表现为“挥到了但什么都没发生”，且随朝向变化呈概率性。

### 建议

用**全部角点**旋转后取 min/max，或直接对局部盒做旋转矩阵变换求完整 AABB：

```java
// 局部盒：x ∈ {±6.5}（按 isRight 取符号），y ∈ {±4}，z ∈ {18, -4}
double angle = Math.toRadians(-getYRot());
double c = Math.cos(angle), s = Math.sin(angle);
double minX = 1e9, maxX = -1e9, minZ = 1e9, maxZ = -1e9;
for (double x : new double[]{6.5 * isRight(), -6.5 * isRight()}) {
    for (double z : new double[]{18.0, -4.0}) {
        double rx = x * c + z * s;
        double rz = -x * s + z * c;
        minX = Math.min(minX, rx); maxX = Math.max(maxX, rx);
        minZ = Math.min(minZ, rz); maxZ = Math.max(maxZ, rz);
    }
}
AABB box = new AABB(
        position().x + minX, position().y - 4.0, position().z + minZ,
        position().x + maxX, position().y + 4.0, position().z + maxZ
);
```

各近战武器的局部盒尺寸不同（如 Gassan 的 z 为 28..36，Mitake 的 x/y 为非对称布局），建议按各武器实际 `pilePos1/pilePos2` 生成角点。

## 2. 蓄力开火只判定“单 tick 精确相等”，过于脆弱

```java
public boolean isOnFire() {
    if (motion.getType().equals(Motion.MotionType.CONTINUOUS) && ...) {
        return true;
    } else if (motion.getType().equals(Motion.MotionType.CHARGE)) {
        return currentActionTick == fireStartTick + 5;   // 只有这一帧为 true
    }
    ...
}
```

### 问题

整个 AOE 结算（伤害、击退、音效、破坏方块）都依赖 `currentActionTick` 恰好等于 `fireStartTick + 5`。客户端与服务端的动作状态只要错位一拍（输入同步延迟、掉帧、动作被其他逻辑打断），这一帧就会被跳过，整次挥击无效。

### 建议

- 把单 tick 相等改为区间判定：`currentActionTick >= fireStartTick + 5 && currentActionTick < fireStartTick + 5 + N`（N 取动画生效帧数，如 3~5），让命中判定覆盖挥击动画的有效帧；
- 或引入一次性事件状态：`fireAction()` 置位 `firePending`，由 action 管理器在动画到达命中帧时消费并结算，避免依赖 tick 计数的精确相等。

## 3. 单 tick 一次性 AABB 查询，容易漏掉移动中的目标

伤害只在开火那一帧查询一次静态 AABB。挥击动画跨多帧，目标在动画期间移动或刚进入范围时可能漏判。

### 建议

在挥击有效窗口内做多 tick 判定（配合建议 2 的区间），或用上一帧到本帧的扫掠 AABB（swept AABB）做命中检测，与子弹的命中判定思路一致。

## 4. 单发重击会被目标 20 tick 无敌帧完全吞掉

`le.hurt(ds, damage)` 使用普通伤害源，不绕过目标的无敌帧（`invulnerableTime > 0` 时直接返回 false）。近战是单发高伤，如果目标在挥击前 1 秒内被任何来源击中过（例如同机甲的持续武器），这一发会被完整吞掉，只保留击退。

### 建议

- 近战结算使用可绕过无敌帧的伤害类型（`bypasses_invulnerability`），或命中前单独清除目标的 `invulnerableTime`；
- 至少在伤害计算时不与持续武器共用同一套无敌帧窗口。

## 5. 燃料/部件不足时，正在进行的蓄力动作被整体重置

```java
private void resetAllActionsWhenNotActive() {
    if (this.isBroken() || !this.canWork(false) || !this.isVehicle()) {
        for (Action a : actionController.getAllActions()) {
            if (a.isInAction()) {
                a.reset();
            }
        }
    }
}
```

`canWork(false)` 包含 `getFuelNow() != 0`。蓄力中的武器一旦在蓄力窗口内燃料归零，动作会被静默重置，既没有释放也没有反馈，玩家会看到“开始蓄力了但永远不会打出去”。

### 建议

- 燃料不足时保留已蓄力的进度并给出提示（HUD/音效），而不是直接 `reset()`；
- 或区分“无法开始新动作”与“打断已有动作”，只在真正需要时打断。

## 6. 原生 AI 每 tick 整体覆盖 driverInput，外部驾驶输入会被替换

`MechAutoController.tick()` 每 tick 调用 `mech.setDriverInput(currentInput)`，用自己计算的按键位整体替换输入。当机甲同时存在外部驾驶意图（玩家或其他 AI 单位）时，两套输入互相覆盖，蓄力武器的“按下-释放”边沿可能因此丢失（释放边沿依赖上一帧的输入状态）。

### 建议

- 为输入提供明确的优先级或合并机制（例如外部驾驶优先，原生 AI 只补足空白位）；
- 或只在“无外部驾驶输入”时运行原生 AI 的武器逻辑。

## 7. 调试便利性：伤害盒可视化

近战伤害盒的塌缩问题在实机中很难凭肉眼发现。建议在客户端提供一个可开关的调试选项，把每个近战武器开火帧的 AABB 渲染出来（简单线框即可），便于作者和测试者快速定位判定范围是否与动画一致。

---

以上问题均可在 alpha.8 源码中直接定位。第 1 项是实测中影响最严重的问题（挥击无伤害），其余为稳定性与体验优化建议。

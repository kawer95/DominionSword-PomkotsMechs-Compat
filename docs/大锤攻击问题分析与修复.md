# 大锤（Takao）攻击无伤害问题分析与修复

## 1. 问题现象

统御之剑单位驾驶 PMVC01 使用大锤（Takao）近战攻击时，挥击**有时完全不造成伤害**：

- 有攻击动作/动画；
- 没有击退；
- 没有 AOE 伤害；
- 看起来就像攻击从未发生。

连续砸地时该现象尤为明显（“连续砸地不扣血”），且表现为**概率性**。

## 2. 调试过程与日志证据

1.8.23 起加入服务端调试日志，前缀：

- `[DS-POMKOTS-TAKAO]`：动作 tick、`startAction` / `fireAction(release)` / `RESET-while-active`、开火帧伤害盒内容（`fireAOE`）；
- `[DS-POMKOTS-INPUT]`：每 tick 我们提交的按键位、上一帧按键位、原生 AI 的按键位；
- `[DS-POMKOTS-MOVE]`：移动控制帧、`driveTo` / `stopMovement` / `stop()` 调用。

复现时日志显示：

```text
[DS-POMKOTS-TAKAO] weaponTick mech=b5b5f9ac... tick=7 onFire=true
[DS-POMKOTS-TAKAO] fireAOE mech=b5b5f9ac... box=[-200.9,134.0,544.4 -> -199.5,142.0,569.9] entities=25 living=[]
[DS-POMKOTS-TAKAO] effects spawned ...
```

关键点：

1. `tick=7 onFire=true` —— 开火帧**正常触发**，每次挥击都会走到伤害结算分支；
2. `effects spawned` —— 地面特效、火花、飞溅正常生成；
3. `fireAOE ... living=[]` —— **伤害盒内没有任何活物**；
4. 伤害盒 `box=[-200.9 ... -> -199.5 ...]` 的 X 方向只有 **1.4 格**宽，整条盒子塌成了一条沿对角线的细缝。

对比正常命中时的日志：

```text
fireAOE ... box=[-211.6,134.0,538.9 -> -187.4,142.0,547.2] entities=76
          living=[僵尸#4e3b3c77 hp=20.0 d=5.0 | 小女仆#f7309c48 hp=20.0 d=3.9 | ...]
```

结论：**不是开火帧丢失，也不是特效问题，而是原生伤害盒的判定范围塌缩，目标不在盒子里**。

## 3. 根因分析

### 3.1 原生伤害判定代码

`TakaoItem.tickWeaponInAction`（Pomkots Mechs alpha.8 原版，`TakaoItem.java`）：

```java
var pilePos1 = new Vec3(6.5 * mechInterface.isRight(), 4.0F, 18F)
        .yRot((float) Math.toRadians(-mechInterface.getYRot()))
        .add(mechInterface.position());
var pilePos2 = new Vec3(-6.5 * mechInterface.isRight(), -4F, -4F)
        .yRot((float) Math.toRadians(-mechInterface.getYRot()))
        .add(mechInterface.position());

for (var ent : world.getEntities(null, new AABB(pilePos1, pilePos2))) {
    if (mechInterface.isSelf(ent)) continue;
    if (ent instanceof LivingEntity le) {
        le.knockback(...);   // 击退在伤害之前，且不受无敌帧影响
        le.hurt(ds, ...);    // 伤害
    }
}
```

### 3.2 缺陷：旋转盒只取两个对角点

挥击体积是一个绕机甲旋转的盒子。`new AABB(p1, p2)` 只对**两个对角点**取 min/max：

- 机甲正对 X 或 Z 轴时，两个对角点正好是轴对齐盒子的角，结果正确；
- 机甲带任意角度转向后，这两个点是旋转盒的一对对角，它们 min/max 出来的轴对齐盒只覆盖旋转盒的**对角线细缝**，而不是完整包围盒。

数学上，旋转盒的真实轴对齐包围盒需要对**全部 8 个角**（水平方向 4 个角）取 min/max；只取两个对角会在某个方向上严重塌缩。实测例：机甲转向约 27° 时，伤害盒 X 方向只剩 1.4 格，站在正前方 5 格的目标完全不在盒内。

### 3.3 为什么“像攻击没发生”

击退和伤害在同一个实体循环里，且击退先执行。目标不在盒子里时，循环里根本没有这个目标：

- 没有击退；
- 没有伤害；
- 开火帧与特效照常（它们用的是另一个、正确的落点计算）。

这正好对应“有攻击动作、无击退、无伤害、像攻击没发生”。

### 3.4 为什么是“有概率”

伤害盒的塌缩方向与机甲朝向强相关：某些朝向下细缝恰好扫过目标（命中），另一些朝向下细缝偏开（落空）。攻击期间机甲在转向、目标在移动，于是表现为概率性。

### 3.5 影响范围

该缺陷不是大锤独有。alpha.8 里所有近战武器都是同一个写法：

| 武器 | 局部盒子（isRight 作用于 x） |
| --- | --- |
| Takao（大锤） | x ±6.5，y ±4，z -4..18 |
| Tsurugi（剑） | x 6.5..-2，y ±4，z -4..18 |
| Kagenobu（景信/打桩机） | x 6.5..-2，y ±4，z -4..18 |
| Tenpou（天宝） | x 6.5..-2，y ±4，z -4..18 |
| Jinba（仁波） | x 6.5..-4，y ±4，z -4..18 |
| Gassan（月山） | x 6.5..-2，y ±4，z 28..36 |
| Mitake（三竹） | x -2.5+r..2.5+r，y -2.5..5，z 0..10 |

## 4. 修复方案

### 4.1 工具类 `MeleeAabbFix`

新增 `util/MeleeAabbFix.java`：

```java
public static AABB rotatedBox(Vec3 pos, float yaw, double[] xs, double[] ys, double[] zs) {
    double angle = Math.toRadians(-yaw);
    double cos = Math.cos(angle), sin = Math.sin(angle);
    // 对 xs × ys × zs 全部 8 个角做与原生相同的旋转，再取 min/max
    // 返回 pos + 旋转后的完整轴对齐包围盒
}
```

与原生一致的旋转公式（`Vec3.yRot(-yaw)`）：

```text
rx = x·cos(-yaw) + z·sin(-yaw)
rz = -x·sin(-yaw) + z·cos(-yaw)
```

### 4.2 每个近战武器一个 Mixin

对 7 个武器各建一个 mixin（`TakaoMeleeAabbMixin`、`TsurugiMeleeAabbMixin`、`KagenobuMeleeAabbMixin`、`TenpouMeleeAabbMixin`、`JinbaMeleeAabbMixin`、`GassanMeleeAabbMixin`、`MitakeMeleeAabbMixin`）：

1. `@Inject` 到 `tickWeaponInAction` 的 HEAD，`isOnFire` 为 true 时按该武器的局部几何计算完整盒，存入 `ThreadLocal`；
2. `@Redirect` 原生 `new AABB(p1, p2)` 调用，返回完整盒。

示例（Takao）：

```java
@Inject(method = "tickWeaponInAction(...)", at = @At("HEAD"), remap = false)
private void dominion$storeCorrectedAabb(ActionWeapon.WeaponMechInterface mech, int tick,
                                         boolean isOnFire, CallbackInfo ci) {
    if (!isOnFire) return;
    double r = mech.isRight();
    dominion$correctedAabb.set(MeleeAabbFix.rotatedBox(mech.position(), mech.getYRot(),
            new double[]{6.5 * r, -6.5 * r}, new double[]{4.0, -4.0}, new double[]{18.0, -4.0}));
}

@Redirect(method = "tickWeaponInAction(...)",
        at = @At(value = "INVOKE",
                target = "Lnet/minecraft/world/phys/AABB;<init>(Lnet/minecraft/world/phys/Vec3;Lnet/minecraft/world/phys/Vec3;)V"),
        remap = false)
private AABB dominion$fullRotatedAabb(Vec3 p1, Vec3 p2) {
    AABB box = dominion$correctedAabb.get();
    return box != null ? box : new AABB(p1, p2);
}
```

要点：

- 不改动原生逻辑，只替换伤害判定盒；
- 各武器的局部几何严格照抄原版 `pilePos1 / pilePos2`；
- 远程武器、导弹等不在此列，不受影响。

## 5. 验证方法

1. 复现原问题：连续砸地，观察 `[DS-POMKOTS-TAKAO] fireAOE` 日志。
2. 修复后日志同时打印 `fixed=[...]`（完整盒）与 `old=[...]`（原生细缝）：
   - `fixed` 盒内应包含目标（`living=[...]` 非空）；
   - 目标血量下降、击退出现。
3. 多朝向测试：机甲分别以 0° / 30° / 90° / 任意角面向目标，正前方目标均应命中。
4. 顺带回归其他 6 个近战武器。

## 6. 相关发现（仍在跟踪）

### 6.1 动作生命周期（已排查，非本次原因）

CHARGE 武器的开火要求 `currentActionTick == fireStartTick + 5` 单 tick 精确相等；释放边沿依赖 `DriverInput` 的 `prevInput` 链。调试日志确认本场景下开火帧每次都正常到达，因此不是本次无伤害的原因。日志里也保留了 `startAction / fireAction(release) / RESET-while-active`，可用于排查动作被提前重置的情况。

### 6.2 攻击结束后机甲单向漂移（待复现）

表现：攻击结束后机甲有概率朝一个方向持续前进，直到手动干涉。已加入 `[DS-POMKOTS-MOVE]`（控制帧变化、`driveTo` / `stopMovement` / `stop()`）与 `[DS-POMKOTS-INPUT]`（我们 vs 原生 AI 的输入位）日志，等待复现日志确认是控制帧残留、pilot 输入残留还是原生 AI 接管。
